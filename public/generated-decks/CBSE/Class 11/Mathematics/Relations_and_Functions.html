Cartesian Product: Formal Definition

  • For two non-empty sets A and B, the Cartesian product A × B is the set of all ordered pairs (a, b).
  • Here, 'a' is an element of set A, and 'b' is an element of set B.
  • A × B = { (a, b) : a ∈ A, b ∈ B }

🎙️ The key here is 'ordered pairs'. The order matters! (a, b) is generally not the same as (b, a). This product creates a new set containing all possible pairings between elements of A and B.

Cartesian Product: An Example

  • Let A = {1, 2} and B = {a, b, c}.
  • A × B = { (1, a), (1, b), (1, c), (2, a), (2, b), (2, c) }
  • B × A = { (a, 1), (a, 2), (b, 1), (b, 2), (c, 1), (c, 2) }

🎙️ Notice that A × B is not equal to B × A. Also, if set A has 'p' elements and set B has 'q' elements, then A × B will have 'p × q' elements. This is a crucial point for counting elements.

Key Properties of Cartesian Product

  • If A or B is an empty set, then A × B is an empty set.
  • If A or B is an infinite set, then A × B is an infinite set.
  • A × B ≠ B × A (unless A = B or one of them is empty).

🎙️ These properties are crucial for understanding how Cartesian products behave. Remember that the number of elements in A × B is the product of the number of elements in A and B, which simplifies counting.

Relation: Formal Definition

  • A relation R from a non-empty set A to a non-empty set B is a subset of the Cartesian product A × B.
  • The subset is derived by describing a relationship between the first element and the second element of the ordered pairs.
  • R ⊆ A × B

🎙️ So, every relation is essentially a collection of ordered pairs, where each pair follows a specific rule. This rule defines how elements from set A are related to elements from set B. It's a specific connection within all possibilities.

🤝

Relation: An Example

  • Let A = {1, 2, 3} and B = {2, 3, 4, 5}.
  • Define a relation R from A to B as R = { (x, y) : x ∈ A, y ∈ B, and x < y }.
  • R = { (1, 2), (1, 3), (1, 4), (1, 5), (2, 3), (2, 4), (2, 5), (3, 4), (3, 5) }

🎙️ First, imagine A × B. Then, we apply the condition 'x < y' to filter out only the pairs that satisfy it. These selected pairs form our relation R. This demonstrates how a rule generates a specific subset.

Domain, Codomain, and Range of a Relation

  • **Domain:** The set of all first elements of the ordered pairs in a relation R.
  • **Codomain:** The entire set B from which the second elements are taken.
  • **Range:** The set of all second elements of the ordered pairs in a relation R.

🎙️ Think of the domain as the 'inputs' that are actually used, and the range as the 'outputs' that are actually produced by the relation. The codomain is the potential pool of all outputs, whether used or not.

🎙️ In this example, every element of A is used, so the domain is A. Every element of B is hit by at least one arrow, so the range is B. This clarifies the practical application of these terms.

The Empty Relation (Void Relation)

  • A relation R in a set A is called an empty relation if no element of A is related to any element of A.
  • It's denoted by the empty set, ∅.
  • R = ∅ ⊆ A × A

🎙️ Imagine a relation 'is taller than' among students in a class where all students are exactly the same height. No one would be taller than anyone else, resulting in an empty relation. It's a relation with no pairs.

The Universal Relation

  • A relation R in a set A is called a universal relation if each element of A is related to every element of A.
  • It means R = A × A.
  • Every possible pair is included.

🎙️ Consider the relation 'x is a friend of y' in a group where everyone is friends with everyone else, including themselves. This would be a universal relation, encompassing all possible pairings within the set.

The Vending Machine Analogy for Functions

  • You press a button (input), and you get a specific item (output).
  • Every input button gives *exactly one* output item.
  • No button gives two different items, and no button gives nothing.

🎙️ A function is a very special kind of relation. It's precise and predictable. For every valid input, there is one and only one specific output. This strict rule makes functions very powerful in mathematics.

🥤

Function: Formal Definition

  • A relation f from a set A to a set B is said to be a function if every element of set A has one and only one image in set B.
  • This means for each x ∈ A, there is a unique y ∈ B such that (x, y) ∈ f.
  • We write f: A → B.

🎙️ The two critical conditions for a relation to be a function are: 1. Every element in the domain (set A) must be used. 2. Each element in the domain must map to exactly one element in the codomain (set B). Both must hold!

Function: An Example Mapping

  • Consider f = {(1, a), (2, b), (3, c)}.

Domain, Codomain, Range of a Function

  • For a function f: A → B, the set A is the **domain** of f.
  • The set B is the **codomain** of f.
  • The set of all images of elements of A is the **range** of f.

🎙️ For functions, the domain is always the entire starting set A. The codomain is always the entire ending set B. The range is a subset of the codomain, containing only the actual outputs produced by the function.

Identifying Functions: The Vertical Line Test (Graphical)

  • If you can draw a vertical line anywhere on the graph that intersects the graph at more than one point, it's NOT a function.
  • Each x-value (input) must correspond to only one y-value (output).
  • This test is primarily for functions from R to R.

🎙️ This is a powerful visual tool for quickly determining if a given graph represents a function. If any vertical line cuts the graph more than once, it means one input has multiple outputs, violating the function definition.

Common Real Functions

  • **Identity Function:** f(x) = x. Input is output.
  • **Constant Function:** f(x) = c. Output is always 'c'.
  • **Polynomial Functions:** f(x) = a₀ + a₁x + ... + aₙxⁿ. General form.

🎙️ These are the basic building blocks. You'll work extensively with polynomial functions, and understanding identity and constant functions provides a strong foundation for more complex function types.

Common Mistakes to Avoid!

  • Confusing Cartesian Product with Union/Intersection.
  • Forgetting that order matters in ordered pairs (a,b) ≠ (b,a).
  • Not checking BOTH conditions for a relation to be a function (every element of A used, unique image).
  • Mixing up Codomain and Range.

🎙️ These are typical areas where students lose marks. Pay close attention to definitions and practice carefully to avoid these errors in your exams. Precision is key in this topic.
