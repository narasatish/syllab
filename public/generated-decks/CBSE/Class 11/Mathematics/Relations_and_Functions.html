Introducing the Cartesian Product of Sets

  • If A and B are two non-empty sets, A × B is the set of all ordered pairs (a, b).
  • Here, 'a' belongs to set A and 'b' belongs to set B.
  • A × B = { (a, b) : a ∈ A, b ∈ B }

🎙️ The Cartesian Product is like creating every possible pairing between elements of two sets. It's a foundational concept that generates the 'universe' of possible relationships between the elements of two sets.

Cartesian Product: A Worked Example

  • Let A = {1, 2} and B = {a, b, c}.
  • A × B = {(1, a), (1, b), (1, c), (2, a), (2, b), (2, c)}.
  • Number of elements: n(A × B) = n(A) × n(B) = 2 × 3 = 6.

🎙️ Here's a simple example to illustrate the Cartesian Product. Notice how each element from set A is paired with every element from set B, creating all possible ordered pairs. The total count of these pairs is simply the product of the number of elements in each set.

What Exactly is a Relation?

  • A relation R from a non-empty set A to a non-empty set B is a subset of the Cartesian product A × B.
  • It defines a specific connection or rule between elements of A and B.
  • R ⊆ A × B

🎙️ A relation is not just any random collection of pairs; it's a specific rule or condition that selects certain pairs from the Cartesian product. It formalizes how elements of one set are 'related' to elements of another.

Domain, Codomain, and Range of a Relation

  • Domain: The set of all first elements (x-coordinates) of the ordered pairs in R.
  • Range: The set of all second elements (y-coordinates) of the ordered pairs in R.
  • Codomain: The entire set B (the set to which the relation maps).

🎙️ Understanding domain and range is crucial. The domain tells us what inputs are actually used in the relation, and the range tells us what outputs are actually produced. The codomain, on the other hand, is the entire target set, irrespective of whether all its elements are mapped to.

Relation Example: Finding Domain and Range

  • Let A = {1, 2, 3, 4}, B = {1, 4, 9, 16, 25}.
  • Relation R: 'is the square of' from A to B.
  • R = {(1, 1), (2, 4), (3, 9), (4, 16)}.
  • Domain(R) = {1, 2, 3, 4}. Range(R) = {1, 4, 9, 16}.

🎙️ In this example, we define a specific rule: 'is the square of'. We then find the pairs that satisfy this rule. The domain consists of all the first elements that participate, and the range consists of all the second elements that are actually reached by the relation.

Common Mistake: Relation vs. Cartesian Product

  • A relation is NOT always the entire Cartesian Product.
  • It is a SUBSET, meaning it can be smaller or equal.
  • Always check the specific rule/condition of the relation.

🎙️ A very common error is to assume a relation includes all possible pairs. Remember, the Cartesian Product is the 'universe' of pairs, and a relation is a selection from it based on a given rule. Always read the relation's definition carefully.

The Empty (Void) Relation

  • A relation R on a set A is empty if no element of A is related to any element of A.
  • R = ∅ ⊂ A × A.
  • Example: R = {(a, b) : a, b ∈ A, a - b = 10} on A = {1, 2, 3}.

🎙️ An empty relation means that the given rule or condition is never satisfied by any pair of elements from the set. It's a relation with no ordered pairs, an empty subset of the Cartesian product.

No Connections

The Universal Relation

  • A relation R on a set A is universal if every element of A is related to every element of A.
  • R = A × A.
  • Example: R = {(a, b) : a, b ∈ A, |a - b| ≥ 0} on A = {1, 2, 3}.

🎙️ The universal relation is the opposite of the empty relation. Here, every possible pair from the Cartesian product satisfies the given condition. It includes all ordered pairs.

What is a Function? A Special Type of Relation

  • A function 'f' from set A to set B (f: A → B) is a relation.
  • Condition 1: Every element in set A must have an image in set B.
  • Condition 2: Each element in set A must have a UNIQUE image in set B.

🎙️ Functions are very specific relations. They are like well-behaved machines. Every input must go somewhere, and it can only go to one specific output. This 'every' and 'unique' condition is what differentiates a function from a general relation.

Function as a 'Machine' Analogy

  • Input (from Domain) goes into the machine.
  • The machine (function) processes the input.
  • A unique Output (in Range) is produced.
  • No input is left unprocessed, no input gives multiple outputs.

🎙️ Imagine a vending machine: every button you press (input) must dispense a product (output), and pressing the same button always gives the exact same product. This analogy perfectly captures the two conditions for a function.

Domain, Codomain, and Range of a Function

  • Domain: The entire set A (all possible inputs).
  • Codomain: The entire set B (all possible outputs).
  • Range: The set of all actual outputs, f(A) = {f(x) : x ∈ A}.

🎙️ For a function, the domain is always the entire starting set A. The codomain is the entire target set B. The range is a subset of the codomain, containing only those elements that are actually mapped to by the function.

Worked Example: Identifying Functions

  • Set A = {1, 2, 3}, Set B = {a, b, c}.
  • R1 = {(1, a), (2, b), (3, c)}: Is it a function? (Yes)
  • R2 = {(1, a), (2, b)}: Is it a function? (No, 3 has no image)
  • R3 = {(1, a), (1, b), (2, c), (3, c)}: Is it a function? (No, 1 has two images)

🎙️ Let's apply the two function conditions to these examples. R1 satisfies both. R2 fails because element 3 from set A is not mapped. R3 fails because element 1 from set A is mapped to two different elements in set B.

Common Mistake: Forgetting Function Conditions

  • Mistake 1: Not checking if EVERY element of the domain is mapped.
  • Mistake 2: Not checking if each element has a UNIQUE image.
  • Both conditions MUST be satisfied for a relation to be a function.

🎙️ These two conditions are the most frequent pitfalls when determining if a relation is a function. Always explicitly verify both: 'every element' and 'unique image'. Missing either will lead to incorrect conclusions.

Graphical Representation of Functions: Vertical Line Test

  • A graph represents a function if and only if every vertical line intersects the graph at most once.
  • If a vertical line intersects the graph more than once, it means one x-value has multiple y-values.
  • This violates the 'unique image' condition of a function.

🎙️ The Vertical Line Test is a powerful visual tool to quickly determine if a given graph represents a function. If any vertical line passes through more than one point on the graph, then it's not a function, as it implies a single input producing multiple outputs.

Summary & Key Takeaways

  • Cartesian Product: All possible ordered pairs.
  • Relation: A subset of the Cartesian Product (a rule).
  • Function: A special relation (every element mapped, uniquely).
  • Domain, Codomain, Range are crucial for both.

🎙️ We've covered the fundamental concepts of relations and functions today. Remember the hierarchy: Cartesian Product contains Relations, and Functions are a special type of Relation. Always be clear on domain, codomain, and range definitions.
